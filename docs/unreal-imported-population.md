# Imported capital and camp population

The assignment source is `shared/data/importedPopulation.json`: 18 owner-supplied
FBXs, 11 appearance replacements, six new Bastion inhabitants, eight new Riftspire
inhabitants, and four camps containing six friendly inhabitants and seven hostile
melee enemies. Source filenames are provenance, never new character names.

Current local status (2026-09-27): all 18 bodies and their supplied animations
are imported privately; 288 native review frames and 38 clear proposed
placements are recorded. Live layers have not been changed. Sunmeadow and
Cinderfen generated packages differ from their historical receipts; automatic
approval review requires owner approval before guarded reconciliation. The
default apply path refuses that drift. `WAR_POPULATION_RECONCILE_OWNER=1` is
reserved for explicitly approved reconciliation, with exact current-package
hashes and retained-actor comparisons. Gameplay, saved-world views and expanded
population performance remain unfinished until placement can proceed.

`capital_population.planned_records()` exposes both capitals without changing
the existing live population until native admission. Named services, Mara,
existing encounters and wildlife retain their identities. New traders and
scholars are ambient inhabitants, not newly implemented services. Camp leaders
use ordinary melee behavior, not boss mechanics.

## Preparation and review

```powershell
python scripts/unreal/animation-pipeline.py capital-camps --review
python scripts/unreal/animation-pipeline.py population-paladin --from-stage retarget --review
python tests/unrealImportedPopulation.test.py
npx vitest run tests/unrealImportedCamps.test.ts
npm run unreal:imported-population-proof
npm run unreal:population-proof -- --rendered
```

Run Unreal stages sequentially with the editor closed. Individual
`population-<model key>` recipes reuse the measured rig and supplied clips.
Outputs are private under `artifacts/unreal/imported-population`; staged visual
definitions and loadouts live under `/Game/Characters/PopulationImports`.
Body import reuses the existing material importer. Achromatic specular inputs
are translated to Unreal scalar specular; colored or textured specular remains
an explicit unsupported case. Missing texture links are inventoried, and their
material appearance must be reviewed before admission.

The ledger records explicit dielectric material corrections for Erika, Vampire
and Maw: legacy Phong reflection values otherwise become metallic cloth/skin.
Their original embedded color textures are retained. Review commandlets disable
texture streaming to capture full-resolution inputs; this is not a runtime
streaming policy change. Separate civilian frames hide attached combat gear.

The Brute's supplied `BattleAxe_GEO` is excluded from the prepared body so its
porters are unarmed and fighters cannot receive duplicate weapons. Its original
FBX is retained. The equipped Paladin and archer retain their authored props.
Other combat loadouts reuse existing native equipment with per-rig transforms;
Riftspire enforcers and camp bruisers use the scavenged equipment family.

The pipeline does not activate new visuals in the global import registry or
change the live city. `place-imported-population.py` defaults to a non-saving
grounding/standing-clearance survey. Applying requires `WAR_POPULATION_APPLY=1`
and exact `development-review.json` evidence covering native packages,
materials, equipped motion, the placement survey and navigation. A failed gate
must leave the affected work unfinished, without substitute models.

The survey compares the current saved actor state, preserving owner changes
to existing names, roles, transforms and unrelated content. Review fingerprints
use sorted fields and 0.01 cm placement precision to exclude physics rounding
noise. A successful apply records all affected package hashes and actors;
another run verifies that receipt and does not duplicate inhabitants. The
`preview` stage reloads saved layers and captures close-ups and district/camp
views without saving inspection lights or camera actors.

The runtime proof visits Riftspire and all four camp zones. It checks exact
identities, advancing friendly idles, equipment readiness, ambient service and
combat boundaries, and hostile visual/catalog readiness. It then reuses the
existing enemy proof for each distinct hostile model, including pursuit,
attacks, leash/reset, death, unloading/reloading and respawn. `--population-only`,
`--combat-only`, or `--enemy <stable actor ID>` supports focused rechecks.

## Private content and acceptance

Raw `modelImport` files and generated native content are ignored. Distribution
rights are unverified; no raw assets are published or added to the public repo.
Skeleton/pose checks and native review images do not establish gameplay,
packaged-platform, Steam or production acceptance. Existing release gates remain
closed. Private receipts distinguish prepared, imported, reviewed and placed
states; the source ledger deliberately does not grant native art approval.
